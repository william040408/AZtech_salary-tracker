GitHub·Cloudflare·Google 아래에 일곱 개의 서비스가 따로 돌고 있습니다. 각각이 무엇이고, 왜 그 자리에 있고, git push 가 정확히 무엇을 움직이는지를 바닥부터 설명합니다.

읽는 법. 새 용어는 굵게 나오고 바로 뒤에 뜻이 붙습니다. 별명(문지기 같은)에는 항상 소속 · 정식 명칭 을 같이 적었습니다. 맨 뒤에 용어 사전이 있습니다.

02바닥부터 — 인터넷에서 무슨 일이 일어나나

클라이언트와 서버

서버(server)는 요청을 받아 답을 돌려주는 프로그램입니다. 그 프로그램이 도는 컴퓨터도 서버라고 부릅니다. 클라이언트(client)는 요청을 보내는 쪽입니다. 웹에서는 브라우저가 클라이언트입니다.

"서버를 빌렸다"는 말은 24시간 켜져 있고 요청에 답하는 컴퓨터를 빌렸다는 뜻입니다. 특별한 기계가 아닙니다.

HTTP — 주고받는 약속

HTTP(HyperText Transfer Protocol)는 클라이언트와 서버가 대화하는 규칙입니다. 프로토콜(protocol)은 주고받는 형식에 대한 약속을 뜻합니다. HTTPS 는 그 대화를 암호화한 것으로, 중간에서 엿들어도 내용을 알 수 없습니다.

메서드 — 무엇을 하려는지

요청에는 메서드(method)가 붙습니다. 무엇을 하려는지 알리는 한 단어입니다.

메서드뜻우리 시스템에서
GET달라화면 파일, 급여 데이터 읽기
PUT이걸로 바꿔라금고에 데이터 쓰기
POST이걸 처리해라일꾼 깨우기
OPTIONS뭐가 허용되나브라우저가 미리 물어봄 (뒤에 설명)

상태 코드 — 결과를 알리는 숫자

응답 맨 앞에는 상태 코드(status code)가 붙습니다. 세 자리 숫자로 결과를 알리는 것입니다.

코드뜻언제 보나
200성공정상
401신원 확인 실패암구호가 틀렸을 때
404그런 것 없음없는 주소를 부를 때
500서버가 터짐설정이 빠졌을 때

주소 — 어디의 무엇인지

https://william040408.github.io/AZtech_salary-tracker/
└─┬─┘   └────────┬────────────┘└────────┬───────────┘
프로토콜      호스트(도메인)            경로

도메인(domain)은 서버를 가리키는 사람이 읽을 수 있는 이름입니다. 실제 컴퓨터는 IP 주소(숫자로 된 주소)로 찾는데, DNS(Domain Name System, 도메인을 IP로 바꿔주는 전화번호부)가 그 변환을 해 줍니다. 그래서 주소를 치면 브라우저가 먼저 DNS에 물어보고, 받은 IP로 요청을 보냅니다.

03GitHub — 세 개의 서비스

GitHub 은 한 회사, 한 계정 아래 여러 서비스를 묶어 둔 것입니다. 우리는 그중 셋을 씁니다. 셋은 서로 자동으로 엮이지 않습니다.

① 창고 — GitHub · Repository

Git은 파일의 변경 이력을 기록하는 프로그램이고, 리포지터리(repository, 줄여서 repo)는 그 이력이 담긴 저장 공간입니다. GitHub 은 그 저장 공간을 인터넷에 올려 두는 서비스입니다.

기록 단위를 커밋(commit)이라 부릅니다. "이 시점의 파일들을 이런 이유로 이렇게 바꿨다"는 한 덩어리입니다. 지금까지 30번 넘게 쌓였고, 아무 시점으로나 되돌릴 수 있습니다.

git push 는 노트북의 커밋을 창고로 보내는 명령입니다. 브랜치(branch, 갈라진 작업 줄기)는 여럿 만들 수 있는데 우리는 main 하나만 씁니다.

② 자판기 — GitHub · Pages

정적 호스팅(static hosting)입니다. 미리 만들어 둔 파일을 요청한 그대로 돌려주기만 하는 서비스를 뜻합니다. "정적"(static)은 요청마다 내용이 달라지지 않는다는 뜻입니다.

계산도, 판단도, 기억도 하지 않습니다. 그래서 빠르고 공짜지만 입력을 저장할 수 없고, 누가 요청하든 똑같이 내줍니다. 급여 숫자를 여기 둘 수 없는 이유입니다.

Pages 는 창고의 docs 폴더만 내보내도록 설정돼 있습니다. 창고가 바뀌면 그 폴더를 다시 읽어 갑니다.

③ 일꾼 — GitHub · Actions

CI/CD 도구입니다. 원래는 코드가 바뀔 때마다 자동으로 검사하고 배포하는 용도(Continuous Integration / Continuous Delivery)인데, 실체는 "명령을 대신 실행해 주는 일회용 컴퓨터"입니다.

깨어날 때마다 러너(runner, 실제로 명령을 실행하는 가상 컴퓨터)가 새로 만들어집니다. 매번 빈 상태로 시작하고 일이 끝나면 통째로 사라집니다. 이 성질이 나중에 중요한 문제를 만듭니다(⑨장).

무엇을 할지는 워크플로(workflow, 단계별 작업 정의 파일)에 적습니다. 우리 파일은 .github/workflows/refresh.yml 이고, YAML(들여쓰기로 구조를 나타내는 설정 파일 형식)로 쓰여 있습니다.

언제 깨어날지는 트리거(trigger, 실행 조건)가 정합니다. 우리는 workflow_dispatch 하나만 걸어 뒀습니다. "밖에서 불러야만 깨어난다"는 뜻입니다. 그래서 git push 로는 일꾼이 깨어나지 않습니다.

04Cloudflare — 두 개의 서비스

④ 문지기 — Cloudflare · Workers

서버리스(serverless) 방식입니다. 서버가 없다는 뜻이 아니라, 서버를 내가 관리하지 않는다는 뜻입니다. 요청이 올 때만 코드가 잠깐 실행되고 끝납니다. 놀고 있을 때는 비용도 자원도 쓰지 않습니다.

엣지(edge)에서 돕니다. 전 세계에 흩어진 서버 중 요청자와 가장 가까운 곳을 뜻합니다. 그래서 응답이 빠릅니다.

자판기와 결정적으로 다른 점은 판단을 한다는 것입니다. 우리가 준 지시사항이 worker/worker.js 이고, 이렇게 적혀 있습니다.

  • 암구호가 틀리면 401 만 돌려주고 끝내라
  • 맞으면 금고에서 꺼내 줘라
  • 우리 사이트에서 온 요청만 받아라
  • /refresh 요청이 오면 일꾼을 깨워라

⑤ 금고 — Cloudflare · Workers KV

키-값 저장소(key-value store)입니다. 이름표(키)를 붙여 값을 넣어 두고, 그 이름표로 꺼내는 가장 단순한 형태의 데이터베이스입니다. 사물함을 떠올리면 됩니다.

키값
bundle명세서 6장 + 근태 203일
leave달력에 찍은 분류
config시급, 소정근로시간, 입사일
meta마지막 갱신 시각

값은 JSON(중괄호와 따옴표로 자료를 표현하는 글자 형식)으로 저장합니다. 사람도 읽을 수 있고 프로그램도 바로 해석할 수 있어서 널리 쓰입니다.

05Google — 메일을 여는 부분

⑥ 메일함 — Google · Gmail

매달 이카운트가 "문서가 도착했다"는 알림 메일을 보냅니다. 그 메일 본문에는 금액이 한 글자도 없습니다. 링크 하나뿐입니다.

IMAP — 메일을 읽는 규칙

IMAP(Internet Message Access Protocol)은 서버에 있는 메일을 프로그램이 읽어 가는 프로토콜입니다. 메일을 보낼 때 쓰는 SMTP 와 짝을 이룹니다. 우리는 읽기만 하므로 IMAP 만 씁니다.

브라우저는 IMAP 을 말하지 못합니다. 브라우저가 할 수 있는 건 HTTP 하나뿐입니다. 일부러 그렇게 막아 둔 것입니다 — 아무 웹사이트나 방문자의 메일을 읽을 수 있으면 큰일이니까요.

그래서 웹 버튼이 직접 메일을 열 수 없고, IMAP 을 말할 수 있는 ③ 일꾼(GitHub Actions)에게 시키는 것입니다.

앱 비밀번호 — 프로그램 전용 열쇠

프로그램이 메일함에 들어가려면 로그인이 필요합니다. 그런데 진짜 계정 비밀번호를 주는 건 위험합니다. 그 하나로 Gmail·드라이브·유튜브·결제가 전부 열리고, 2단계 인증(비밀번호 외에 휴대폰 확인을 한 번 더 하는 것)을 켜 두면 어차피 통과도 못 합니다.

앱 비밀번호(app password)는 특정 프로그램 하나만을 위해 따로 발급하는 16자리 비밀번호입니다.

계정 비밀번호앱 비밀번호
범위구글 전체IMAP·SMTP 접속만
개수하나용도별로 여러 개
폐기바꾸면 전부 재로그인그것만 삭제
2단계 인증거쳐야 함묻지 않음

더 좁은 권한이 필요하면 OAuth(비밀번호를 주지 않고 "메일 읽기"처럼 특정 권한만 위임하는 방식)를 써야 하지만, 설정이 훨씬 복잡해서 쓰지 않았습니다. 그래서 앱 비밀번호는 "Gmail 읽기"가 아니라 "Gmail 전체 접근"이라는 점은 알고 있어야 합니다.

⑦ 문서 창구 — 이카운트 전자문서

메일의 링크를 따라가면 명세서가 열립니다. 그 과정이 이렇습니다.

  1. 메일 본문의 l.ecount.com/···· — 단축 URL (짧은 주소를 실제 주소로 바꿔 주는 중계)
  2. 중계 페이지로 넘어가고, 그 페이지의 자바스크립트가 실제 주소를 계산
  3. 세션(session, "이 사람이 맞다"는 상태를 잠시 기억해 두는 것)이 만들어지고 명세서 화면이 뜸

링크는 3개월이면 만료됩니다. 이카운트가 그렇게 정해 뒀습니다. 실제로 2~5월분은 이미 만료돼서 받아올 수 없었고, 남아 있던 텍스트로 겨우 복구했습니다. 매달 한 번은 받아 둬야 하는 이유입니다.

헤드리스 브라우저 — 사람 없이 페이지 열기

위 과정은 자바스크립트가 돌아야 완성됩니다. 단순히 주소를 부르는 것만으로는 안 됩니다.

그래서 헤드리스 브라우저(headless browser, 화면 없이 동작하는 진짜 브라우저)를 씁니다. 우리가 쓰는 도구가 Playwright 입니다. 크롬을 화면 없이 띄워 페이지를 열고, 자바스크립트가 다 돌기를 기다린 뒤, 완성된 화면에서 글자를 읽어 옵니다.

이카운트의 내부 동작을 흉내 내지 않고 진짜 브라우저가 진짜로 페이지를 열게 두었기 때문에, 이카운트가 내부를 바꿔도 잘 깨지지 않습니다.

06인증 — 누가 무엇을 열 수 있나

공유 비밀 — 암구호

가장 단순한 방식입니다. 공유 비밀(shared secret)은 양쪽이 같은 값을 알고 있고, 그 값이 일치하면 통과시키는 것입니다.

우리 페이지는 요청마다 헤더(header, 요청에 덧붙이는 부가 정보 칸)에 x-pass: 암구호 를 실어 보냅니다. ④ 문지기가 자기가 가진 PASSPHRASE 와 비교합니다.

토큰 — 프로그램용 신분증

토큰(token)은 프로그램이 쓰는 비밀번호인데, 사람 비밀번호와 세 가지가 다릅니다.

  • 권한을 좁힐 수 있습니다. 우리 GH_TOKEN 은 "이 저장소의 Actions 만" 건드릴 수 있습니다
  • 여러 개를 따로 만들 수 있습니다. 하나가 새면 그것만 폐기하면 됩니다
  • 만료 기한을 둡니다. 우리는 1년으로 잡았습니다

CORS — 브라우저가 미리 물어보는 것

브라우저에는 동일 출처 정책(same-origin policy)이 있습니다. 어떤 사이트의 스크립트가 다른 주소로 요청을 보내는 것을 기본적으로 막는 규칙입니다. 악성 사이트가 몰래 내 은행 서버에 요청을 보내는 걸 막기 위한 장치입니다.

그런데 우리 페이지는 github.io 에 있고 데이터는 workers.dev 에 있습니다. 출처가 다릅니다. 그대로면 브라우저가 막습니다.

이걸 푸는 방식이 CORS(Cross-Origin Resource Sharing, 서버가 "저 출처는 허용한다"고 밝히면 브라우저가 통과시켜 주는 규칙)입니다. 문지기가 응답에 이렇게 적어 보냅니다.

Access-Control-Allow-Origin: https://william040408.github.io

브라우저는 본 요청을 보내기 전에 OPTIONS 로 한 번 미리 물어봅니다. 이걸 프리플라이트(preflight, 사전 확인 요청)라 합니다. Cloudflare 설정의 ALLOW_ORIGIN 이 바로 이 값입니다.

시크릿 — 비밀을 두는 곳

시크릿(secret)은 암호화해서 보관하고 실행할 때만 꺼내 쓰는 값입니다. 코드 파일에 적으면 창고에 올라가 공개되므로, 각 플랫폼이 제공하는 시크릿 저장소에 넣습니다. 로그에도 *** 로 가려져 찍힙니다.

노트북에서는 환경 변수(environment variable, 프로그램에 값을 전달하는 이름표) 형태로 .env 파일에 둡니다. 이 파일은 .gitignore(창고에 올리지 않을 파일 목록)에 들어 있습니다.

07전체 구성도

가장 흔한 오해. "GitHub 이 Cloudflare 한테 데이터를 넘겨준다" — 그런 일은 없습니다. 둘이 직접 이야기하는 경우는 딱 두 번이고 둘 다 Cloudflare 가 GitHub 에게 말을 거는 방향이며, 급여 데이터와 무관합니다.

  • 코드를 올릴 때 — Cloudflare 가 창고에서 문지기 코드를 가져감
  • 버튼을 누를 때 — 문지기가 GitHub API 로 일꾼을 깨움

08상황별로 무엇이 움직이나

㉮ 코드를 고쳐 올릴 때 — git push

금고는 건드리지 않습니다. 그래서 코드를 아무리 고쳐도 급여 데이터와 달력 기록은 그대로입니다.

㉯ 사이트를 열었을 때

  1. DNS 로 주소를 찾고 ② 자판기에 GET 숫자가 하나도 없는 화면 파일이 옵니다. 이 파일은 누구나 받을 수 있습니다.
  2. 브라우저가 HTML·CSS·JavaScript 를 읽어 화면을 그림 아직 표가 비어 있습니다.
  3. 저장해 둔 암구호를 헤더에 실어 ④ 문지기에 GET 그 전에 브라우저가 OPTIONS 로 프리플라이트를 한 번 보냅니다.
  4. 문지기가 대조하고 ⑤ 금고에서 꺼내 JSON 으로 돌려줌 틀리면 401 만 돌아오고 아무것도 안 옵니다.
  5. JavaScript 가 빈칸을 채움 여기서 처음으로 급여 숫자가 화면에 등장합니다.

09왜 이렇게 나눴나 — 설계 이유

자판기만으로 안 되는 이유

정적 호스팅은 기억도 판단도 못 합니다. 입력을 저장할 곳이 없고, 급여를 두면 누구나 봅니다. 그래서 판단하는 ④ 문지기와 기억하는 ⑤ 금고가 필요했습니다.

버튼이 직접 메일을 못 읽는 이유

브라우저는 HTTP 만 말합니다. IMAP 을 말할 수 없고, 헤드리스 브라우저를 띄울 수도 없습니다. 그래서 그걸 할 수 있는 ③ 일꾼에게 시킵니다.

문지기를 거쳐 일꾼을 깨우는 이유

폰에서 GitHub 을 직접 깨우려면 GH_TOKEN 이 페이지 안에 있어야 하는데, 그러면 페이지를 여는 누구나 그 토큰을 봅니다. 문지기가 대신 들고 있으면 토큰은 서버 쪽에만 남습니다.

계약 조건을 금고에 둔 이유

시급은 최저임금이 오르면 바뀝니다. 설정을 GitHub 시크릿에 복사해 두면 원본을 고쳐도 일꾼은 옛 값으로 계산하는데, 조용히 어긋나서 알아채기 어렵습니다. 금고에 한 벌만 두고 일꾼이 매번 받아 가게 했습니다.

명세서를 덮어쓰지 않고 합치는 이유

③ 일꾼의 러너는 매번 빈 상태로 시작합니다(③장). 그래서 그 시점에 링크가 살아 있는 명세서만 받습니다. 그대로 올리면 링크가 만료된 옛 명세서가 사라지는데 다시 받아올 방법이 없습니다. 실제로 3~5월분이 지워졌다가 복구했습니다. 지금은 기간을 열쇠로 합치고, 금고를 읽지 못하면 아예 올리지 않고 멈춥니다.

10열쇠 여섯

흩어져 있는 게 아니라 일하는 곳마다 그 일에 필요한 것이 하나씩 있습니다. 세 대의 컴퓨터(노트북·문지기·일꾼)는 서로의 저장소를 볼 수 없습니다.

PASSPHRASE 와 WORKER_PASS 는 같은 값입니다. 한쪽은 자물쇠(내가 지키는 문), 한쪽은 열쇠(남의 문을 여는 쪽)라 이름만 다릅니다.

하나가 새도 나머지는 멀쩡합니다. 폰은 GH_TOKEN 을 모르고, 일꾼은 화면을 못 건드리고, 문지기는 메일을 못 읽습니다. 이것을 최소 권한 원칙(least privilege, 각자에게 꼭 필요한 권한만 준다)이라 합니다.

11자주 헷갈리는 것

코드를 고쳐 올리면 명세서도 갱신되나?
아니요. git push 는 ② 자판기의 화면과 ④ 문지기의 규칙만 바꿉니다. 명세서는 버튼을 누르거나 노트북에서 올려야 들어옵니다.
버튼을 누르면 화면 기능도 바뀌나?
아니요. 버튼은 ⑤ 금고 안의 데이터만 갱신합니다.
저장소가 공개인데 급여가 새어나가지 않나?
새어나가지 않습니다. ① 창고에는 급여 숫자가 한 개도 없습니다. 전부 ⑤ 금고에 있고, 암구호가 있어야 열립니다.
Pages 주소를 남이 알면 내 급여를 보나?
못 봅니다. "저장소 연결" 화면만 뜹니다.
Cloudflare 가 멈추면 사이트가 죽나?
화면은 뜨지만 숫자가 안 채워집니다. 반대로 Pages 가 멈추면 화면이 안 뜨지만 금고의 데이터는 그대로입니다. 둘은 따로 움직입니다.
Node.js 를 왜 안 깔았나?
Node.js 는 JavaScript 를 브라우저 밖에서 실행하는 프로그램입니다. Cloudflare 배포 도구(wrangler)가 이걸로 만들어져 있지만, 그 도구는 Cloudflare 쪽 컴퓨터에서 돌아가므로 내 노트북에는 필요 없습니다.
