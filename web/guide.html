읽고 나면 오늘 한 일이 전부 이해됨

급여 기록부 작동 원리

웹을 한 번도 안 해본 사람 기준으로, 파일이 뭔지부터 시작해서 왜 서버를 두 개나 빌렸는지까지 순서대로 설명합니다.

01한 문장으로

매달 이메일로 오는 급여명세서를 자동으로 모아서, 회사 근무기록과 대조해 "이번 달 월급이 왜 이 금액인지"를 폰에서 볼 수 있게 만든 것.

처음에 궁금했던 건 세 가지였습니다.

  • 남은 연차가 몇 개인가
  • 월급이 계산대로 제대로 들어왔는가
  • 연차가 제대로 사용 처리됐는가

명세서를 읽어보니 돈 계산은 전부 정상이었습니다. 6개월치 실수령액 변동이 연차수당과 기본급 차감만으로 100% 설명됐고, 고용보험·주민세 같은 공제도 전부 맞았습니다.

문제는 다른 데 있었습니다. 명세서에 근태 정보가 아예 없습니다. 금액만 있고 며칠 쉬었는지, 연차가 몇 개 남았는지가 안 적혀 있습니다. 그래서 "왜 이 금액인지"를 확인할 방법이 없었습니다. 그걸 채우려고 만든 게 이 도구입니다.

02순서대로 뭘 했나

  1. 명세서에서 급여 구조를 역산했습니다 기본급을 시급으로 나눠보니 딱 떨어지는 시간 수가 나왔습니다. 거기서 시급·월 소정근로시간·하루치 금액을 알아냈고, 연차를 쓰면 기본급에서 시간 단위로 깎인다는 규칙까지 찾았습니다.
  2. 명세서를 자동으로 받아오게 했습니다 이메일 본문에는 금액이 한 글자도 없고 링크만 있었습니다. 그래서 브라우저를 사람 없이 자동으로 띄워서 그 링크를 열고 표를 읽어오게 만들었습니다. 링크는 3개월이면 만료되므로 매달 한 번은 돌려야 합니다.
  3. 회사 근무기록 엑셀과 대조했습니다 엑셀의 빈칸이 두 종류라는 걸 발견했습니다. 그날 전원이 비어 있으면 회사 전체 휴무, 나만 비어 있으면 개인 휴가입니다. 이걸 구분해야 명세서의 차감액과 맞출 수 있습니다.
  4. 화면을 만들었습니다 달력에서 날짜를 눌러 그날의 성격(연차·반차·무급·회사휴무)을 직접 기록하고, 그 기록을 명세서 차감액과 자동으로 대조하는 페이지입니다.
  5. 인터넷에 올렸습니다 폰에서도 노트북에서도 같은 내용을 보려면 인터넷에 있어야 합니다. 오늘 오래 걸린 게 바로 이 단계입니다. 아래에서 자세히 설명합니다.

03웹 기초 — 5분

파일이 전부입니다

웹사이트라고 하면 뭔가 대단한 것 같지만, 실체는 글자가 적힌 파일 몇 개입니다. 브라우저가 그 파일을 읽고 화면을 그리는 것뿐입니다.

HTML — 뼈대

"여기 제목, 여기 표" 같은 구조를 적은 파일입니다. 아래처럼 적으면

<h1>급여·연차 기록부</h1>
<p>9월 11일 연차</p>

브라우저가 읽고 "첫 줄은 큰 제목, 둘째 줄은 본문"으로 그립니다. 레고 조립 설명서와 같습니다. 종이 자체는 별것 아니지만 그대로 조립하면 모양이 나옵니다.

직접 확인해 보세요. 아무 웹페이지에서 마우스 우클릭 → 페이지 소스 보기를 누르면 글자가 잔뜩 나옵니다. 그게 브라우저가 받은 원본 파일입니다.

CSS — 겉모습

뼈대에 색과 크기를 입힙니다. 기록부에 실제로 이런 줄이 있습니다.

.cell.k-personal { background: 연한초록; color: 초록; }

"연차로 찍힌 칸은 연한 초록 배경에 초록 글씨로 그려라"는 뜻입니다. 달력에서 9월 11일이 초록으로 보이는 이유가 이 한 줄입니다.

@media (max-width: 520px) { .cell { min-height: 52px; } }

"화면 폭이 520px보다 좁으면, 즉 폰이면 칸 높이를 52px 이상으로 해라"는 뜻입니다. 폰에서 달력 칸이 손가락으로 누를 만큼 커지는 게 이 덕분입니다.

JavaScript — 움직임

HTML과 CSS는 가만히 있습니다. 눌러도 반응이 없습니다. 움직이게 하는 게 JavaScript입니다. 기록부에서는 이런 일을 합니다.

  • 달력 그리기 — 9월이면 30칸, 2월이면 28칸
  • 날짜를 누르면 아래에서 선택창 올리기
  • 연차 잔액 계산하기
  • 급여 숫자를 받아오기 — 이게 핵심입니다. 뒤에서 다시 나옵니다

셋이 한 파일에 다 들어 있습니다. index.html 하나에 HTML·CSS·JavaScript가 섞여 있습니다. 원래는 나누기도 하지만, 하나로 뭉쳐 두는 쪽이 간단합니다.

서버 — 항상 켜져 있는 남의 컴퓨터

노트북에 있는 index.html은 더블클릭하면 열립니다. 그런데 폰에서는 못 엽니다. 파일이 노트북 안에 있으니까요.

서버 = 전원을 안 끄는 컴퓨터. 파일을 거기 올려두면 인터넷이 되는 아무 기기에서나 꺼내 볼 수 있습니다.

특별한 기계가 아닙니다. 24시간 켜져 있고, 누가 "파일 줘"라고 하면 보내주는 프로그램이 돌고 있는 것뿐입니다. 노트북을 서버로 쓸 수 없는 이유는 단순합니다. 덮으면 꺼지고, 집 인터넷 주소는 계속 바뀌어서 폰이 찾아갈 수가 없습니다.

그래서 남의 것을 빌립니다. GitHub과 Cloudflare가 공짜로 빌려주는 걸 썼습니다.

주소가 하는 일

https://william040408.github.io/AZtech_salary-tracker/
        └──── 어느 컴퓨터 ────┘└───── 어느 폴더 ─────┘

"어느 컴퓨터의, 어느 파일"을 가리키는 게 전부입니다. 집 주소와 같습니다.

04서버에도 두 종류가 있습니다

이게 오늘 오래 걸린 이유의 핵심입니다.

종류 A

자판기 — GitHub Pages

생각을 하지 않습니다. 물어본 파일을 그대로 뱉습니다.

  • 빠르고 공짜
  • 기억을 못 합니다. 폰에서 뭘 입력해도 받아둘 데가 없습니다
  • 판단을 못 합니다. 누가 물어보든 똑같이 내줍니다
종류 B

카운터 직원 — Cloudflare Worker

생각을 합니다. 요청을 받고 내줄지 말지 판단합니다. 우리가 준 지시사항이 worker.js 파일이고, 이렇게 적혀 있습니다.

  • 암구호가 틀리면 "안 됩니다"라고만 답하고 끝내라
  • 맞으면 금고에서 꺼내서 줘라
  • 우리 사이트에서 온 요청만 받아라

그리고 금고(KV)가 직원이 물건을 넣어두는 곳입니다. 급여 데이터와 달력 입력이 여기 들어 있습니다.

05왜 두 개를 썼나

처음엔 GitHub 하나로 하려고 했는데, 자판기라서 두 가지가 막혔습니다.

문제왜어떻게 풀었나
입력을 저장 못 함자판기는 기억을 못 함직원에게 맡김
급여가 공개됨자판기는 아무에게나 내줌급여는 금고에만 넣음

그래서 역할을 갈랐습니다. 화면 파일은 GitHub에, 급여 숫자는 Cloudflare 금고에. GitHub에 올라간 파일에는 급여 숫자가 하나도 없습니다. 그래서 저장소를 공개로 둬도 안전합니다.

06실제로 이렇게 돌아갑니다

폰에서 주소를 열었을 때 벌어지는 일입니다. 화면이 먼저 오고, 숫자가 나중에 따로 옵니다. 이 순서가 이 구조의 전부입니다.

폰과 노트북이 같은 내용을 보는 이유가 여기 있습니다. 입력이 기기에 저장되는 게 아니라 금고에 저장되기 때문입니다. 어느 기기에서 열든 ③④를 거쳐 같은 금고에서 꺼내옵니다.

07GitHub이 정확히 뭐였나

GitHub은 사실 두 가지 일을 합니다. 섞여서 헷갈리기 쉽습니다.

ㄱ) 창고 — 원래 기능

코드 파일을 보관하는 곳인데, 바꾼 기록을 전부 남깁니다.

25번째 저장: 전사 휴무를 처리 방식에 따라 셋으로 나눔
24번째 저장: Worker 배포 방식을 문서에 적음
23번째 저장: wrangler 배포 설정 추가
 ...

언제든 옛날 버전으로 되돌릴 수 있습니다. git push는 "노트북의 파일을 창고로 보내라"는 명령입니다.

오늘 이 기록을 손봐야 했습니다. 초반 커밋 안에 급여 금액과 이름이 남아 있었는데, 저장소를 공개로 올리면 그 옛날 기록까지 전부 읽힙니다. 그래서 25개 커밋 전체에서 금액과 이름을 지우고 올렸습니다. 지금은 흔적이 없습니다.

ㄴ) 자판기 — Pages 기능

창고에 있는 파일 중 docs 폴더만 인터넷에 내보내주는 서비스입니다. 설정에서 /docs를 고른 게 그 뜻입니다.

08고치면 어떻게 반영되나

경로가 세 가지인데, 서로 다릅니다. 이것만 구분하면 됩니다.

무엇을어떻게누가걸리는 시간

달력을 누르는 건 명령어가 필요 없습니다. 누르는 순간 금고에 저장됩니다.

09오늘 오래 걸린 이유

Cloudflare Worker에 코드를 집어넣는 방법이 두 가지인데, 처음 고른 쪽이 막혀 있었습니다.

방법 A — 브라우저에서 직접 타이핑
간단하지만 Worker가 만들어진 방식에 따라 잠겨 있을 수 있습니다. Read only를 만난 게 이것입니다.
방법 B — GitHub에서 자동으로 가져가게 하기
Cloudflare가 저장소를 지켜보다가 바뀌면 알아서 가져가 배포합니다. 이걸 하려면 "뭘 어떻게 배포해라"를 알려줘야 하는데, 그 배달 주문서가 wrangler.jsonc입니다.

A가 막혀서 B로 돌렸는데, 그러던 중 Edit code가 열려서 결국 A로 끝났습니다. 헛수고는 아닙니다. B도 같이 연결해 둔 덕분에 앞으로는 코드를 고치면 자동 배포됩니다.

10매달 할 일

cd 프로젝트폴더
.venv\Scripts\activate

python src/fetch.py links     명세서 링크 수집
python src/fetch_doc.py       명세서 받아오기
python src/report.py          이상한 것만 보고
python src/push_data.py       금고에 반영

명세서 링크는 3개월이면 만료됩니다. 거르면 그달 명세서를 영영 못 봅니다. 이미 2월부터 5월까지는 만료돼서 못 가져왔습니다. 매달 10일 이후에 한 번은 돌려야 합니다.

11용어 정리

HTML
화면의 뼈대를 적은 파일. "여기 제목, 여기 표"
CSS
겉모습을 적은 파일. 색, 크기, 폰에서의 배치
JavaScript
움직임을 적은 파일. 누르면 반응하고, 계산하고, 데이터를 받아옴
서버
전원을 안 끄는 남의 컴퓨터. 파일을 나눠주는 프로그램이 돌고 있음
GitHub
코드 창고. 바꾼 기록을 전부 보관하고, 되돌릴 수 있음
GitHub Pages
창고의 docs 폴더를 인터넷에 내보내주는 자판기
git push
노트북의 파일을 창고로 보내는 명령
Cloudflare Worker
요청을 받고 판단하는 문지기. 암구호를 확인함
KV
문지기가 물건을 넣어두는 금고. 급여·근태·달력 입력이 여기 있음
wrangler
Cloudflare에 배포하는 도구. wrangler.jsonc가 그 주문서
Node.js
JavaScript를 브라우저 밖에서 실행하는 프로그램. wrangler가 이걸로 만들어져 있음. 내 노트북엔 필요 없음 — Cloudflare 쪽 컴퓨터에서 돌아감
Python
내 노트북에서 도는 언어. 명세서 파싱·검산·빌드를 담당
가상환경 (.venv)
이 프로젝트 전용 패키지 보관함. 다른 프로젝트와 안 섞이게 격리
.env
비밀번호를 적어두는 파일. 절대 창고에 올라가지 않음. .venv와 이름만 비슷한 다른 것
