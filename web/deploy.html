git push 하면 정확히 무엇이 움직이는가

GitHub과 Cloudflare, 누가 뭘 하나

두 이름 아래에 사실은 다섯 개의 서비스가 따로 돌고 있습니다. 그걸 나눠 보면 "고치면 반영된다"가 정확히 어떤 경로인지 드러납니다.

01왜 헷갈리나

"GitHub"은 한 가지가 아닙니다. 서로 다른 세 서비스가 한 이름, 한 계정 아래 있을 뿐입니다. Cloudflare도 둘입니다.

그래서 "GitHub이 알아서 업데이트해준다" 는 말이 애매해집니다. 셋 중 무엇이 무엇을 업데이트한다는 뜻인지가 빠져 있으니까요. 이 문서는 그 다섯을 하나씩 떼어 봅니다.

02GitHub의 세 얼굴

① 창고 (Repository)
코드 파일을 보관합니다. 바꾼 기록을 전부 남겨서 언제든 되돌릴 수 있습니다. git push 는 노트북의 파일을 이 창고로 보내는 명령입니다.
② 자판기 (Pages)
창고에 있는 파일 중 docs 폴더만 인터넷에 내보냅니다. 물어본 파일을 그대로 줄 뿐, 생각도 기억도 하지 않습니다.
③ 일꾼 (Actions)
시키면 깨어나서 명령을 실행하고 다시 잠듭니다. 우리는 메일에서 명세서를 받아오는 일을 시킵니다. 평소에는 꺼져 있습니다.

셋은 서로 자동으로 엮이지 않습니다. 창고가 바뀌었다고 일꾼이 깨어나지 않고, 일꾼이 일했다고 자판기가 바뀌지 않습니다. 각각 따로 움직입니다.

03Cloudflare의 두 얼굴

④ 문지기 (Worker)
요청을 받고 암구호를 확인해서 내줄지 말지 판단합니다. 24시간 켜져 있습니다. 우리가 준 지시사항이 worker/worker.js 파일입니다.
⑤ 금고 (KV)
문지기가 물건을 넣어두는 곳. 급여명세서, 근태, 달력에 찍은 분류, 계약 조건이 전부 여기 있습니다.

04가장 흔한 오해

"GitHub이 Cloudflare한테 데이터를 넘겨준다" — 아닙니다.

웹사이트가 열릴 때 둘 사이로는 아무것도 흐르지 않습니다. 폰이 양쪽에 각각 물어봅니다. 자판기에서 화면 파일을 받고, 문지기에게 암구호를 내고 숫자를 받습니다. 둘은 서로를 모릅니다.

둘이 직접 이야기하는 경우는 딱 두 번뿐이고, 둘 다 급여 데이터와는 무관합니다.

언제누가 누구에게무엇을
코드를 올릴 때Cloudflare → GitHub문지기 코드를 가져감
버튼을 누를 때Cloudflare → GitHub일꾼을 깨움

둘 다 Cloudflare가 GitHub에게 말을 거는 방향입니다. 반대 방향은 없습니다.

05코드를 고쳤을 때 git push

이게 가장 자주 일어나는 일입니다. 한 번의 push가 두 곳을 각각 움직입니다.

무엇이무엇을 보고언제
② 자판기docs/index.html약 1분
④ 문지기worker/worker.js
wrangler.jsonc		약 2분
③ 일꾼— (움직이지 않음)—
⑤ 금고— (건드리지 않음)—

금고는 절대 안 건드립니다. 그래서 코드를 아무리 고쳐도 급여 데이터와 달력 기록은 그대로입니다.

06사이트를 열었을 때

  1. 자판기에서 화면 파일을 받습니다 숫자가 하나도 없는 빈 껍데기입니다. 이 파일은 누구나 받을 수 있습니다.
  2. 브라우저가 그 파일을 읽고 화면을 그립니다 아직 표가 비어 있습니다.
  3. 저장해 둔 암구호로 문지기에게 요청합니다 암구호는 처음 연결할 때 그 기기에 저장됩니다.
  4. 문지기가 확인하고 금고에서 꺼내 줍니다 틀리면 아무것도 안 줍니다.
  5. 빈칸이 채워집니다 여기서 처음으로 급여 숫자가 화면에 등장합니다.

07불러오기 버튼을 눌렀을 때

가장 여러 단계를 거칩니다. 브라우저는 이메일을 읽을 수 없기 때문에 남을 시켜야 합니다.

08달력을 눌렀을 때

가장 단순합니다. GitHub은 전혀 관여하지 않습니다.

폰 ──암구호──▶ ④ 문지기 ──▶ ⑤ 금고에 저장
                                    │
       다른 기기에서 열면 ◀──────────┘

누르는 즉시 저장되고, 노트북에서 열면 그 값이 그대로 보입니다. 명령어도 git push 도 필요 없습니다.

09노트북에서 명세서를 넣을 때

python src/push_data.py 는 창고를 거치지 않고 금고로 바로 갑니다. 급여 데이터를 창고에 넣으면 공개되기 때문입니다.

내 노트북 ──암구호──▶ ⑤ 금고
   (창고를 안 거침)

이 명령은 계약 조건(config.json)도 함께 올립니다. 일꾼은 실행할 때마다 금고에서 그 값을 받아가므로, 시급이 바뀌어도 고칠 곳은 노트북의 파일 하나뿐입니다.

10열쇠 여섯 개

열쇠가 흩어져 있는 게 아니라, 일하는 곳마다 그 일에 필요한 것이 하나씩 있습니다. 세 대의 컴퓨터는 서로의 저장소를 볼 수 없어서, 같은 값을 두 군데 넣기도 합니다.

열쇠어디에무엇을 여나
PASSPHRASECloudflare금고 — 문지기가 대조할 원본
GH_TOKENCloudflare일꾼 — 깨우는 신분증
GMAIL_USER
GMAIL_APP_PASSWORD		GitHub메일함 — 일꾼이 씀
WORKER_URL
WORKER_PASS		GitHub금고 — 일꾼이 결과를 넣음
(전부)노트북 .env노트북에서도 같은 일을 하므로

PASSPHRASE 와 WORKER_PASS 는 같은 값입니다. 한쪽은 자물쇠(내가 지키는 문), 한쪽은 열쇠(남의 문을 여는 쪽)라 이름만 다릅니다.

하나가 새도 나머지는 멀쩡합니다. 폰은 GH_TOKEN 을 모르고, 일꾼은 화면을 못 건드리고, 문지기는 메일을 못 읽습니다. 각자 자기 일에 필요한 것만 들고 있습니다.

11자주 헷갈리는 것

코드를 고쳐서 올리면 명세서도 갱신되나?
아니요. git push 는 화면과 문지기 규칙만 바꿉니다. 명세서는 버튼을 누르거나 노트북에서 올려야 들어옵니다.
버튼을 누르면 화면 기능도 바뀌나?
아니요. 버튼은 금고 안의 데이터만 갱신합니다. 화면을 바꾸려면 코드를 고쳐서 올려야 합니다.
GitHub 저장소가 공개인데 급여가 새어나가지 않나?
새어나가지 않습니다. 창고에는 급여 숫자가 한 개도 없습니다. 전부 금고에 있고, 금고는 암구호가 있어야 열립니다.
Pages 주소를 남이 알면 내 급여를 보나?
못 봅니다. 열어도 "저장소 연결" 화면만 뜹니다. 암구호를 넣어야 숫자가 채워집니다.
Cloudflare가 멈추면 사이트가 죽나?
화면은 뜨지만 숫자가 안 채워집니다. 반대로 Pages가 멈추면 화면이 안 뜨지만 금고의 데이터는 그대로입니다. 둘은 따로 움직입니다.

12안 될 때 어디를 보나

증상의심할 곳
화면이 아예 안 뜸② 자판기 — GitHub 저장소 Settings → Pages
"저장소 연결" 화면만 계속 뜸주소나 암구호 오타, 또는 ④ 문지기
숫자가 안 채워짐④ 문지기 — Cloudflare Workers 화면
달력을 눌러도 저장이 안 됨④ 문지기 또는 ⑤ 금고 바인딩
불러오기 버튼이 실패③ 일꾼 — GitHub 저장소 Actions 탭의 로그
고쳤는데 화면이 그대로1~2분 기다린 뒤 새로고침. 그래도면 ② 자판기

어느 쪽이 문제인지 가르는 가장 빠른 방법 — 사이트를 열었을 때 화면이 뜨는지 보세요. 뜨면 자판기는 멀쩡하고, 숫자가 안 채워지면 문지기나 금고 쪽입니다.
